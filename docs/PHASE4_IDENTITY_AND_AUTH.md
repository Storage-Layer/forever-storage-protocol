# Phase 4 Identity & Authorization
X.509 ECDSA P-256 PKI (generated with `openssl` for tests, see [authorization.rs](file:///home/rade/Project/Jobs/fsp/src/security/authorization.rs)). After the TLS handshake chain validation, the leaf SHA-256 fingerprint is looked up in `ClusterTrustPolicy` -> identity + role (Coordinator / StorageNode / ReadOnlyObserver); expiry checked against policy `not_after`; clients additionally bind the peer to the expected `NodeId`. RBAC per RPC op. Rotation adds fingerprints and can revoke old ones. `ProductionStrict` rejects test-only identities. Limitations: no CRL/OCSP; expiry uses the policy's `not_after`, not the certificate's own validity (webpki checks that separately); certificate SAN is `localhost` only for tests; hostname is fixed to `localhost` in the client.
