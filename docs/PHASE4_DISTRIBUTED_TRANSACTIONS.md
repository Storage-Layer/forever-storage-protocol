# Phase 4 Distributed Transactions
PUT: validate id -> take per-object write lock -> encode all stripes -> plan placement -> write `PREPARING` journal (with targets) -> concurrent PutShard (each node journals PREPARING/COMMITTED, verifies stripe SHA-256 and the staged container, atomic rename) -> check ack policy (default all n) -> sign manifest (generation+1) -> atomic manifest write (commit point) -> journal `COMMITTED`. Abort: DeleteShard on targets. Recovery: any `PREPARING` journal -> orphan DeleteShard + `ABORTED`. Node `PutShard` is idempotent per `(tx_id, shard_id)` — **in memory only**; replay detection does not survive a node restart (after restart the same PutShard is simply re-executed, which is still safe because it overwrites identically). GET: verified manifest -> fetch >= k shards, per-shard SHA-256, can_decode rank check, object SHA-256.
Whole object is buffered in the coordinator during PUT (100 MiB measured); not a bounded-memory path.
