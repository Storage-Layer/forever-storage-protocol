# FSP Phase 5.3: Security Findings & Vulnerability Elimination Matrix

## 1. Vulnerability Elimination Overview

| Finding ID | Severity | Vulnerability Description | Root Cause | Phase 5.3 Remediation | Verification Test |
|---|---|---|---|---|---|
| **SEC-5.3-01** | CRITICAL | Stale coordinator with high epoch ($\ge 500$) could issue valid permits post-rebootstrap | Static $+100$ epoch jumping does not fence higher preexisting terms | Implemented monotonic `ClusterIncarnationId` and cryptographic `ClusterAuthorityRecord`. Storage nodes bind to incarnation sequence; old incarnation rejected regardless of numerical epoch. | `test_02_rebootstrap_with_old_higher_epoch_fenced_by_incarnation` |
| **SEC-5.3-02** | HIGH | Split-brain mutations under unverified old-quorum coexistence | Isolated rebootstrap executed without verifying whether old coordinator processes were terminated | Storage nodes verify `operational_isolation_attested` and `old_quorum_fenced`. Unverified coexistence triggers fail-closed mutation freeze (`coexistence_warning_active`). | `test_01_rebootstrap_with_old_leader_still_active_rejected`, `test_08_unverified_old_quorum_coexistence_blocks_mutations` |
| **SEC-5.3-03** | HIGH | False claim of global latest freshness from offline quorum checkpoints | Offline majority checkpoint at term $T$ does not prove no commits occurred at term $T+1$ | Reclassified offline checkpoints as `AuthenticatedCommittedCheckpoint`; `AuthenticGlobalLatest` strictly requires verified live cluster sync proof. Divergent checkpoints flagged as `ConflictingAuthorityEvidence`. | `test_09_quorum_signed_checkpoint_classified_as_authenticated_committed`, `test_11_conflicting_authentic_checkpoints_detected_and_reported` |
| **SEC-5.3-04** | CRITICAL | TOCTOU race condition between GC eligibility check and concurrent repair/commit | Shard eligibility checked without reservation lock; concurrent repair or commit unlinked | Implemented 6-stage deletion lifecycle (`Candidate` $\to$ `EligibilityChecked` $\to$ `DeletionReserved` $\to$ `Tombstoned` $\to$ `Quarantined` $\to$ `PhysicallyDeleted`). Pre-deletion revalidates active repairs and generation watermarks. | `test_13_concurrent_gc_and_repair_on_same_shard_rejected`, `test_14_concurrent_gc_reservation_and_manifest_commit_toctou_prevented` |
| **SEC-5.3-05** | MEDIUM | Accidental private key leakage into backup bundles via regex bypass | String regex scanner only checked ASCII PEM headers; raw binary keys or non-standard encodings bypassed | Introduced `StrictMetadataAllowlist` type-level isolation accepting strictly 32-byte Ed25519 public keys, eliminating secret leakage by construction. | `test_20_raw_binary_secret_exclusion_via_strict_allowlist` |
